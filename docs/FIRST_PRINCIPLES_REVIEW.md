# 阶段 33：从作者目标重构创作闭环

检查日期：2026-09-30。基线：`main=ec2f31a71f5f7839d9f34f03832afa89ced31d4e`。本阶段交付开发分支与 Draft PR；功能验证与真实文学质量评测分开记录。

## 首先定义真正的结果

作者需要持续写出自己愿意保留的故事。单次生成字数、调用多少个 Agent、档案卡片数量和自动化测试数量都不能直接代表这个结果。

一次有效创作至少需要五件事：作者能表达意图；系统知道正式前文；输出承接人物、规则与事件；作者能回看问题和修改；修改后的故事能安全继续。由此得到最小闭环：

**作者意图 → 正式前文与公开档案 → 本章方向 → 正文生成 → 章末回看 → 修改或继续。**

独立创作沿用同一闭环，但正文由作者自己写，系统只保存与分析。

## 仓库检查结论

现有账户隔离、版本、作者写锁、跨 store 事务和无 Key 演示已经有较充分的回归验证，基线 204 项检查全部通过。整体重构应保留这些能力，并围绕创作材料与反馈重新组织上层链路。

| 原问题 | 为什么影响作者 | 本阶段实际处理 |
| --- | --- | --- |
| 正文模型只收到蓝图、公开人物卡和选择，没有章号及正式前章正文 | 第二章可能重讲开篇；已有事件难以约束新事件 | 新上下文模块提供章号、前章结尾、近期摘录、故事起点、词面相关的早期章节及有来源的档案条目；协调、正文与审校复用同一材料 |
| 主编只收到当前消息和蓝图 | “沿用刚才的设定”等多轮意图无法可靠理解 | 读取最近 12 条消息，按最新优先分配 8000 字符；蓝图仍提供稳定的作品方向 |
| 非空字段的模型建议被直接忽略 | 作者补充设定后，不知道哪些改变生效 | 建立字段级提案，展示原值与建议；接受、保留原文、版本冲突和重复操作都有明确合同 |
| 没有本章目标与表达偏好 | 每轮只依赖抽象全书蓝图，作者难以控制眼前章节 | 类型、视角、语气、避免事项按作品保存；本章目标和偏好快照绑定本次运行 |
| 原审校主要产出简短摘要，没有可回看的修改疑问 | 写出了什么与下一次如何改善没有连起来 | 模型可提出最多六项章末疑问；本地检查提示较长段落逐字重复和前章重复；可展开阅读全文，无虚假文学分数 |
| 创建新章仍停留旧章，完成后缺少继续入口 | 作者需要额外寻找下一步 | 新章自动选中并聚焦；章末提供写下一章和回看档案；加入专注模式、Ctrl/Cmd+S 和先保存再导出 TXT |
| 九字段表单缺少结构，部分导演文案固定为旧档案场景 | 不同小说都像同一套模板，蓝图难以浏览 | 蓝图按故事核心、人物关系、世界结构分组；导演文案使用当前人物、章号和作者目标 |

## 架构与数据原则

- 上下文构造成为独立纯函数模块，不承担账户、模型传输或正文写入。后续语义检索与质量引擎可以替换材料选择器，而无需重写事务机制。
- 只使用正式前章正文作为故事依据。未确认旧章修改阻止新生成；一般生成遇到前面的未完成草稿会暂停；既有作者事务冲突恢复例外保留，并将作者草稿作为单独的未确认意图材料，不能冒充正式前文。所有章节内容、标题、revision 和稿本身份都参与来源 token。
- 生成前与模型调用之后重新校验来源。来源或蓝图改变时停止原运行，重试增加缓存代次，防止复用旧选择与旧正文；已被事务证明正式提交的章节仍按既有规则恢复，不重复生成或写章。
- 上下文 JSON 最多 14000 字符，保留前章最后 2400 字符及最多六章近期摘录，补充故事起点与最多两章词面相关的早期摘录。省略数量和材料局限明确提供给模型。词面检索不等同于语义理解或全书记忆。
- 故事人物继续仅持有自己的私有记忆，不获得其他人物私密材料或完整专业上下文。公共报告不返回来源内部 token、缓存代次、原始提示词或私有记忆。
- 作者在模型等待期间修改的蓝图、偏好和建议不会被旧请求静默覆盖。表达偏好改变只影响后续运行，正在运行的一章使用开始时的快照。
- 新字段均有旧数据默认值，无批量数据迁移。唯一正文、既有版本恢复、账户隔离和旧 `/novel` 合同保留。

## 如何验收

新增自动化检查覆盖：正式/草稿/未来章节区分、上下文容量、早期词面召回、多轮主编历史、提案接受与拒绝、作者后改冲突、账户隔离、输入限制、模式门禁、跨章材料一致、偏好快照与重启、正文/蓝图在模型等待期间修改、旧缓存隔离、旧数据默认值和提示词不落盘。

浏览器脚本 [browser_stage33.cjs](../tests/browser_stage33.cjs) 在真实本地 HTTP 服务上验证编辑、保存后导出、专注、章末衔接、蓝图草稿保留、偏好刷新恢复、目标、三选一与全文阅读。可额外使用明确的 fake 模型模式，走真实提案 API 验证采用与保留原文；不拦截 HTTP 响应、不调用真实供应商。1440×900 与 1024×900 检查整页横向溢出、键盘交互和浏览器诊断。

实际命令结果、分支、提交、PR 与 CI 以 [PROGRESS.md](../PROGRESS.md) 为准。历史阶段的独立审计不能借用为本阶段审计结论。

## 效果边界与后续优先级

本阶段修复“生成缺少前文”和“作者意图无法生效”等可证明的机制缺口。它改善创作条件，但没有执行真实模型文学质量 A/B，也没有实现训练、类型蒸馏或自动文风学习。

后续优先做：

1. 使用作者自有或明确授权的文本建立连续章节评测集，比较承接、人物动机、冲突推进、重复、视角和作者采纳情况。保留旧版对照，并记录模型与 token 成本。
2. 将质量反馈绑定正文证据位置，区分事实矛盾、推断和作者有意选择；未经证实的检查不自动拦截或改写。
3. 在此来源合同上加入长篇语义召回、经来源校验的章节摘要与结构计划，评估远章事实遗忘，不仅观察最近几章。
4. 质量引擎证明确有增益后再加入有限次数的自动修订，以及作者暂停修改后重新准备上下文的完整恢复体验。
5. 继续按清晰职责拆分大型 AI 服务和前端工作区；优先抽取纯材料构造与界面组件，保留已经验证的事务写入口。
