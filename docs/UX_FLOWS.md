## 1. 全局导航

```text
产品首页 → 邮箱登录 → 书架 → 新建作品 / 已有作品
                              ├─ 独立创作：编辑正文 ↔ 故事档案 ↔ 作品设置
                              └─ AI 辅助：创作室 → 导演台 ↔ 编辑正文 ↔ 故事档案 ↔ 作品设置
```

工作区统一采用左侧书脊式导航。不同作品模式只展示真实可用入口：独立创作没有 AI 导演台；AI 辅助创作拥有导演台和正文编辑器。

## 2. 登录与账户恢复

### 主流程

1. 用户在首页点击“开始试用”。
2. 输入邮箱并点击“使用邮箱继续”。
3. 登录成功后进入书架。
4. 再次打开网页时，合法会话自动恢复；失效时回到登录页，不丢作品数据。

### 状态

- `idle`：等待邮箱。
- `submitting`：按钮禁用并显示处理中。
- `authenticated`：进入书架。
- `invalid_email`：就地提示格式问题。
- `session_expired`：解释原因并允许重新登录。

手机号和微信入口始终是 `coming_soon`，点击只能解释“即将开放”。

## 3. 书架与新建作品

### 作品卡最低信息

- 标题和非具象封面/角色牌。
- 独立创作或 AI 辅助写作模式；只有 AI 模式显示钴蓝标。
- 已完成章节数、目标或总章节数、总字数。
- 最近编辑时间。
- 当前后台状态：已保存、分析中、生成中、等待关键选择、需要处理、失败可重试。

### 新建作品

```text
点击新建作品 → 选择创作模式
  ├─ 独立创作 → 上传旧稿 / 从空白开始 → 作品编辑器
  └─ AI 辅助写作 → 输入初始想法 → 创作室讨论 → 确认蓝图 → 导演台
```

创作模式创建后固定。若以后需要转换模式，应作为独立产品决策，不在首版暗中支持。

## 4. 独立创作流程

### 4.1 首次导入

1. 作者选择文件或粘贴全文。
2. 系统预览识别出的标题、章节数量、字符数和未识别片段。
3. 作者确认后创建正式正文；确认前不写入正式作品。
4. 任务进入 `analyzing_initial_manuscript`，作者可以离开。
5. 分析完成后生成最新档案和各章快照，并通知作者。

导入失败必须保留原文件/输入并说明失败章节，不能生成“空作品成功”。

### 4.2 网页写作与自动保存

- 输入先进入本地短暂草稿状态，再保存到服务端。
- 顶部明确显示：`保存中`、`已保存`、`保存失败·重试`。
- 离页前如仍未保存，必须尝试保存或警告。
- 同一章节多端冲突不能静默覆盖；至少提示服务器有更新并让作者选择重新载入或保留当前草稿。
- 若后台导演事务已写入 commit marker，保存入口会先尝试完成或补偿该事务；不能安全合并时保存被明确阻止并提示“作者修改冲突，可重试”，不覆盖作者 revision。

### 4.3 完成本章

```text
editing → saving → submitted → analyzing → ready
                                     └→ failed_retryable
```

- 点击前先确保正文保存成功。
- `analyzing` 不锁死编辑器，但再次提交同一版本应幂等，不能重复扣分或生成重复快照。
- 分析结果区分：确定更新、疑问点、无变化。
- 作者可撤销本次档案更新；撤销不删除正文。

## 5. 故事档案与章节快照

- 入口默认 `latest`，标题显示“当前状态 · 截至第 N 章”。
- 快照选择器支持跳转到任意已有章节；历史快照只读，并明显标出“第 N 章时”。
- 每条人物状态、剧情线、伏笔和疑问点都有来源章节。
- 回到最新状态是显式操作，不能把历史快照误编辑为当前状态。
- 疑问点可标记：保留观察、这是刻意安排、需要回看、已处理。首版不强迫作者逐条处理后才能继续写。

## 6. 旧章集中修改

### 6.1 待确认阶段

```text
正式正文 V1
  └─ 编辑第 3/8/20 章 → 形成同一批 pending_changes → 自动保存但不触发重建
```

- 页面持续显示“有 N 章修改尚未确认”。
- `pending_changes` 记录基准稿本版本、章节范围、差异摘要和最后修改时间。
- 修改最新章和旧章都可进入同一批；只有作者点击“确认全部修改”才结算。

### 6.2 确认弹层

系统先显示：修改章节、增删字符、影响范围、建议为“忽略”或“重建”。建议不替作者做决定。

作者只能选择：

- **忽略轻微措辞修改并继续**：把待确认正文提交为当前正文，保留现有档案和快照，记录“未重建”。
- **根据当前全文重建档案后继续**：创建同一作品的新稿本版本，提交当前全文，旧分析立即失效，启动全量分析。

取消弹层不会丢待确认修改。

### 6.3 保留与恢复

- 重建前的旧正文版本进入 30 天恢复期。
- 恢复前必须预览将恢复的版本和影响；恢复动作本身产生新的当前版本，不直接改写历史记录。
- 过期清理是后台策略，首版界面至少显示到期时间；不得用修改文件时间代替业务到期时间。

## 7. AI 创作室

### 对话合同

- 前台参与者只有“你”和“主编”。
- 每轮对话只追问影响作品方向的少量问题，不做长表单轰炸。
- 后台专业角色状态可以是：等待、分析、已建议、需补充；它们不直接占据对话流。
- 蓝图字段显示来源与完成度，但不使用虚假百分比制造精确感。

### 蓝图状态

```text
drafting ↔ discussing → ready_to_confirm → confirmed → director_ready
```

确认前允许修改；确认后若重开蓝图，应明确提示会影响后续未生成内容，不静默改写已有正文。

## 8. AI 导演台

### 运行状态

```text
queued → character_simulation → writing → reviewing → updating_archive → completed
            ↑ pause / resume                         └→ failed_retryable
            └→ waiting_for_choice → chosen → continue
```

- 顶部展示正在处理的章节、当前阶段、已用/预算积分和暂停按钮。
- 关闭页面后后台任务继续；重新进入能从服务端恢复状态。
- 暂停在安全检查点生效，不能把半段正文伪装为完成章节。
- 失败时展示可理解原因、是否扣分和重试入口。
- `author_revision_conflict` 是明确的可重试失败：作者正文保留，AI 正式章、快照和完成通知不显示；重试创建新的事务键，旧事务只保留安全恢复证据。

### 关键节点

- 节点包含当前情境和三个互斥选项。
- 作者选择一个后继续同一条正文；选择结果记入作品事件和角色可知信息。
- “把决定交给角色”也是一个正常选项。
- 可能后果默认隐藏；设置开启后才展示，而且不能暗示结果绝对确定。

### 记忆边界

```text
共享世界观/公共事件
  ├─ 角色 A 私有记忆
  ├─ 角色 B 私有记忆
  └─ 角色 C 私有记忆
```

角色私有记忆只写入其亲历、被告知或合理推断的信息。导演与后台专业角色可读取全局资料，但生成角色行动时必须使用该角色的可知视角。

## 9. 通知与积分

- 通知事件至少覆盖：首次分析完成、章末分析完成、全量重建完成、AI 章节完成、等待关键选择、任务失败。
- 通知可从书架和作品内查看；不依赖浏览器页面一直打开。
- 任何消耗积分的动作在开始前说明预计消耗，完成后记录实际消耗；失败是否退回必须有明确状态。
- 内置角色牌、普通保存和浏览历史不消耗创作积分。

## 10. 作品拆解的可恢复状态

阶段 34 在确定性深度结果之外接受模型范围报告。作者先试拆并预览，采用后保存为来源绑定的卷；各卷证据使用文档身份解歧。旧卷正文没有变化时，追加后续章不影响该卷核对；旧解读和旧稿本只读。

全文任务由作者主动启动，后台分段产生新增/修正声明，最后执行综合。暂停会保留已完成结果并阻止在途响应覆盖正文派生结果；在途费用仍记账。页面离开与服务重启均不清空游标或预算。

阶段 32 升级流程按 [冻结合同](STAGE_32_CONTRACT.md) 实施：已有 1.0 基础结果首次进入深度页时，显示待生成深度报告的 `rebuild_required`，有未确认修改时先确认修改；显式重建创建 2.0 运行，旧结果和证据保持历史只读。该流程已经后端、前端和真实浏览器验收。

独立作品完成导入或章节后，拆解事件与正文保存结果一起进入服务端 outbox。作者可以离开页面；服务端会按 `queued → running → completed` 推进，失败显示 `failed_retryable` 和重试入口。服务重启、重复读取和重复触发不会创建重复结果。

拆解页面以 `effective_status` 作为作者应采取的主状态，同时显示 `run_status`、来源是否匹配和当前进度。正文有未确认修改时不显示旧结果为当前结果；来源变化时只能查看历史定位并明确只读，不能把证据带到当前同编号章节。证据回链使用绑定稿本的版本、revision/hash 与 UTF-16 偏移，供浏览器准确定位。

完成态先显示总览，再通过人物、剧情、伏笔、章节节奏、读者体验和文笔技法六个键盘可达标签切换视角。重要结论打开证据抽屉；当前来源可选中 UTF-16 精确片段，历史来源显示只读上下文并禁用定位。1024 与 1440 宽度下页面本身不产生横向溢出。


### 人物与大剧情反馈更新

人物卡默认两段短文：性格/为人和关键经历；详细身份、动机及引用折叠。剧情总览按完整事件或副本组织，支持跨章范围。局部样板为序幕与莫家庄两个节点。已实测人物展开、大事件点击、键盘时间切换、编辑器准确选中文句、390px 窄屏无页面横溢；控制台无错误/警告。修复多版分析复用证据 ID 时读取旧文档的问题，并补齐超过六条依据的展示。141 项隔离测试通过。
