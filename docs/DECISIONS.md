# 叙脉产品决定记录

本文件记录已经拍板的稳定决定，不记录每次讨论过程。新决定若替代旧决定，要直接标明替代关系，并同步更新产品规格、交互和验收。

## 2026-08-10 · 首版产品基线

### 品牌与方向

- 产品名确定为“叙脉”。
- 唯一小标语确定为“新一代写作体验”。
- 首版以前端原型 A“故事档案室”为主；A 的首页最佳，整体最均衡。
- B“夜航排演室”和 C“未来活字”保留为后续局部视觉灵感，不作为首版实现基准。

### 产品结构

- 保留两条入口，名称固定为“独立创作”和“AI 辅助写作”。
- 首版核心页面确定为：产品首页、登录、书架/新建作品、独立编辑器、故事档案、AI 创作室、AI 导演台。
- 独立创作没有 AI 导演台；AI 辅助写作同时有导演台、编辑正文和故事档案。

### 独立创作

- 接受“首次全量导入，之后逐章追加”的长期项目模式。
- 网页是主要载体，正文和状态需要服务端保存并支持多端继续。
- 接受“写作时安静，章末集中检查”。
- 点击完成本章后更新角色状态、剧情线、伏笔、疑问点和快照。
- OOC、冲突、重复、矛盾不直接判错，统一进入低压力的“疑问点”。
- 接受“确定内容自动更新、随时可撤销；不确定内容进入疑问点”。
- 档案默认显示最新状态，并可切换到任意章节查看当时快照。

### 修改与版本

- 修改旧章不创建新作品，而是在同一作品内创建新稿本版本并从头分析。
- 旧分析立即替换；旧正文保留 30 天可恢复。
- 编辑过程只保存待确认修改；作者主动点击“确认全部修改”才结算，不按每字或每章生成版本。
- 系统展示修改范围并提出建议，但作者始终最终选择“忽略轻微措辞修改并继续”或“根据当前全文重建档案后继续”。
- 独立创作和 AI 辅助作品共用这一修改逻辑。

### 角色图片

- 首版纳入可选 AI 角色试绘。
- 首次分析只自动分配内置非具象角色牌，不消耗积分，不提前固定外貌。
- 作者选完画风后按需生成具体角色，不自动生成全员插画。

### 后台任务

- 接受“后台分析、可离开页面、完成后通知”，不要求作者停留在等待页。

### AI 辅助写作

- 作者先与一个统一“主编”讨论并补全蓝图，后台专业角色不轮流占据聊天界面。
- 确认蓝图后，AI 可以自行轮转完成角色推演、正文生成、审查与档案更新，不要求作者逐段审核。
- 每个故事角色拥有私有记忆；角色之间不共享私有记忆，但共享世界观及必须知道的事实。
- 作者以“导演”方式在关键节点选择少量选项。
- 不同时维护多条平行正文；选择后继续唯一正式正文。
- “提前展示可能后果”放在设置，默认关闭。

### 账户与后台

- 首版先完成邮箱登录；手机号、微信页面预留但不真正实现。
- 未来正式发布前建设管理员平台：查看账户、创作积分、模型 token/成本，创建账户并充值。
- 管理员功能不属于当前首版实现。

### 暂不做

- 分享、公开发布、一键投稿、隐私中心等外围页面。
- 平行正文、分支树长期维护。
- 自动全员插画。
- 原生移动端、真实支付、手机号/微信真实登录。

## 变更规则

新智能体不得自行推翻以上决定。如果代码实现需要偏离，先把原因和影响写入根目录 `BLOCKED.md`，由产品讨论形成新决定后再更新这里。

## 2026-08-11 · commit marker 后作者 revision 并发收敛

- 作者正文永远优先。导演事务在持久化 commit marker 时记录稿本 revision；marker 后发现作者 revision 漂移时，AI 不得覆盖作者正文。
- 所有会改变 active version、章节 revision 或 pending changes 的作者写入口，都必须先与同作品未终结的导演事务使用持久、跨进程的项目写锁串行化；不能安全先完成事务时，返回明确可重试的作者修改冲突。
- 若 marker 后已有外部旧代码写出更高 revision，系统只在能证明无冲突并保留作者内容时幂等完成；否则把事务持久收敛为 `author_revision_conflict`/superseded：作者 revision 保留，AI run 为失败可重试，AI 正式章、快照和完成通知不可见，不扣开发积分，安全 usage 元数据保留。
- 跨 store 事务使用 durable journal 的补偿状态和 commit marker。补偿可在启动、worker、公开读取、选择和重试入口重复执行；未达到终态时公开入口以同一作者优先视图返回，不抛 `IndependentServiceError` 或 500。旧事务无补偿字段时继续按已有 payload 兼容恢复。
- 冲突后的重试创建新的事务/幂等键，旧事务不得复活或重复投影；普通选择仍记录 `author`，把决定交给角色及 worker 恢复仍记录 `character`。

## 2026-08-11 · 开发版知识收口与质量边界

- 阶段 27 独立审计已通过；当前发布目标是 GitHub 开发版，不是生产上线，也不创建正式 Release 或 Tag。
- 项目外离线质量门研究 Q2 已验证：36 例脱敏黄金集的硬标签宏 F1=1.000、semantic-needed 覆盖率 1.000、14 项测试通过、外部请求/Token/费用为 0。研究目录不复制、不安装到主仓库。
- Q2 离线研究仍未接入叙脉运行时；真实生成质量增益、产品集成和 Q3 真实模型 A/B 仍 pending。文学质量阶段 23B 结论为 C，功能审计通过不等于小说质量通过。
- 当前开发测试没有正式支付；无 Key 演示和 live 开发模型均按 0 创作积分处理。生产账户、支付、管理员、云同步和公网安全承诺不在本开发版范围。

## 2026-08-12 · V1 主线与阶段同步制度

- 以 `codex/v1-project-closeout` 的 V1 开发版替代旧 `main`，通过 GitHub PR #1 合并后成为新的主线基线；旧 `main` 不再代表现役产品。
- 从本决定起，每个研发、修复、审计或质量阶段都使用独立的 `codex/stage-<编号>-<主题>` 分支。阶段完成并通过本阶段门禁后，必须提交并推送到 GitHub；不得只保留在本机工作树。
- 每个阶段必须在 `PROGRESS.md` 记录分支、提交和 PR（如有）。需要后续审计或总设计师复核的阶段先保持 Draft PR；通过对应门禁后才能合并到 `main`。
- 分支同步不等于生产发布。真实密钥、`.novel_*` 本地数据、审计现场、浏览器现场和项目外质量研究仍不得提交。
