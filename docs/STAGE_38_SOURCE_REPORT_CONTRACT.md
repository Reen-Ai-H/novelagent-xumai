# 阶段38 · 新请求来源引用合同

状态：已决定，待实现和独立复核。旧失败结果不按新合同补写采用。

## 目标

让模型专注人物、剧情及有据纠正，程序负责来源编号和引文装配。普通网页入口、公开报告、用户操作及总预算不变。

## 数据与阶段

1. 新任务持久冻结私有wire版本及短来源目录，例如C1P005。目录严格一一对应当前完整来源库，并绑定账户、版本、revision/hash；未编号文本仍完整发送。恢复时核验目录与同一来源，不能从当前新稿重新配号解释旧结果。
2. SourceReportDraft不让模型声明evidence表；全部支持引用只选已给短ID。旧ReportDraft及EV声明继续按旧路径严格验证。新旧任务显式分流，不能从候选外形猜版本。
3. 先严格检查schema、源边界、唯一且可寻址的对象ID。仅可定位的内容结构问题进入有界诊断及原有review；错误ID不能被服务器悄悄改为“最像的”来源。意外异常不包装成可忽略提示。
4. review读取同一完整原文、草稿、原值hash及诊断，只能accept、一次revise或blocked。修订仍最多8目标、12KiB；证据声明不再是新协议的可写目标。纠错理由必须引用同一目录内的实际来源，不能用“降低确定性”或删除仍成立事实掩盖错误。
5. 对最终候选严格解析来源，确定性构建旧内部格式与引文；完整validate_draft及原import门禁不得削弱。有修订时还要verify，不允许第二次修订。即使模型accept，只要完整校验失败就不采用。
6. 逐阶段保存响应、草稿、诊断、修订和来源版本；重启不重复收费。旧失败历史保留，不能当作新协议成功稿。正常2/有修订3阶段，每阶段最多一次格式修复，总计最多6HTTP；24,576/8,192/4,096输出容量和双预算边界不变。

## 必须证明

- source目录稳定且全量无损：错章、未知、缺失、重复引用、目录/版本被换、账户串用都不得被猜补。
- 有源修订可解决定位明确的未知引用/时序矛盾；review错误accept、修订未解决、无据撤回、超8目标或12KiB、伪造hash/来源均拒绝。
- 人物代词、别名、动作主体/对象、关系方向、真实阶段、时序DAG、逐字唯一引用与源CAS原门禁仍运行；短编号真实不等于结论成立。
- 新旧任务、旧EV、旧失败JSON、重启、缓存响应、未知transport、并发点击、共享费用与旧报告保留回归。
- 实际完整请求核算预留；自动测试不调用真实模型。主集成基线790项，新增测试不能靠skip、弱化断言或删旧合同过关。
- 通过后仍须实际作者账号、完整六章、平台正常入口真实运行及独立语义/浏览器验收，不能只交新协议或候选文件。
