基线：`642ab21`，分支`codex/stage-38-platform-deconstruction`。继承A版视觉与正文/来源/预算安全约束；替代阶段37“独立验收副本即可交付”的口径。目标来源为作者10/20最新目标与Notion全部20项，不只筛选未通过项。

## 用户能完成什么

用指定的真实测试邮箱登录同一网站，点击书架作品直接进入工作台；上传原稿后自动形成编号正确的正式章节，逐章编辑；点击拆书后在同一作品看到主要人物/配角、有据人物总关系图与事件总图，从对象详情直接核对原文。刷新、离开再回仍可用。默认页面简洁，技术材料不占首屏。

## 本轮验收矩阵

| 要求 | 必须核实的证据 |
| --- | --- |
| 所有意见进入实施 | 读全部Notion行，逐项对照反馈，不因未验收/已通过旧标签漏新意见；保留原文 |
| 正确账户与入口 | 实际登录指定邮箱→书架→作品；左下角真实账号和大写首字母头像；直接登录链接不显示错误首页 |
| 自动正式分章 | 从未修过的TXT/MD/DOCX正常上传→自动第一章至第六章→确认；不手工设六个切点，不硬编码标题 |
| 正文不丢与导航 | 分章拼接等于原稿，章号有序且标题不重复编号；六章切换/保存/刷新/返回；原稿旧版本可追溯 |
| 平台内完整报告 | 正常显式入口→费用确认→真实模型→验证→同书可见，不能只交本地JSON或空状态；真实身份、角色、动作与关系核对 |
| 图形减少阅读负担 | 人物与事件总图可读、边有意义且可点，单对象详情按需；1440/1024/390px、键盘、返回和证据定位 |
| 费用及失败 | 既有5元轮余额共享每HTTP预留，失败和未知不放账，旧报告不覆盖、来源变动不采用、并发不重复付费 |
| 独立与发布 | 不同Sol审查P0/P1清零，实际浏览器而非仅fixture；Git分支/Draft PR/同SHA CI，Notion按实际结果再提验 |
| 经验沉淀 | 实际完成后更新product-design技能，记录账户一致性、入口到结果完整验收、反馈不以标签过滤等可复用经验 |
