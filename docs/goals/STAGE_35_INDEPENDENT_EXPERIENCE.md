# 阶段 35 · 独立创作体验与识别优化

## 目标

作者可以可靠导入章节、安静编辑，并通过简洁的人物与剧情展示理解作品；人物误识别和章节误切分有可复现的改善。项目进展以 Notion 功能与效果表对作者负责。

基线为阶段 34 候选 e5cb94e，分支 codex/stage-35-independent-experience。开工离线实跑 297 tests / 0 failures / 0 errors / 0 skipped。阶段 34 真实内容终审继续保留其待验证状态。

## 实施范围

1. 导入识别从工作区服务抽出可独立验证的解析模块，支持中文数字（含百/千/零/两）、阿拉伯数字、Markdown/英文标题、卷与章、序章与尾声；区分目录、正文、短标题和正文里的编号句。保留未归类片段，章节稳定排序，确认前可核对预览。
2. 人物识别整理候选来源、称谓边界、正反证据与跨句出现，解决普通词语/景物/群体误判，保留明确人物、复姓、姓名与动作粘连、否定场景和来源定位。不预设人物上限作为质量指标，不引入重型依赖或为姓名白名单写样例。
3. 独立创作窗口强化正文中心、目录导航、保存状态与拆解入口。导入预览突出章节和未归类片段；分析页突出人物/剧情摘要、有效范围与证据，次要技术信息折叠。保留保存冲突、历史只读、当前来源定位、可访问性和移动端操作。
4. 使用成熟方案官方资料作小范围机制对照，结论进入实现依据，不照搬功能清单。
5. Notion 建立五列主表与全部功能/当前重点/等你验收三视图，纳入正文安全、历史恢复、账户隔离与费用约束。每次交付更新真实证据，不填写主观完成百分比。

## 设计与边界

继承 A 版霜纸/纯纸/墨蓝/钴蓝/朱批，中文正文宋体、界面无衬线、数字等宽。以章节索引和原文回看作为签名；主界面减少说明堆叠，不增加 AI 代写入口。桌面 1440×900、1024×900 和 390px 宽度均可完成关键操作。

只改必要的解析/识别/呈现边界，保留 FastAPI、当前前端和本地存储、API 兼容、正文/版本/账户/预算保护。不读取输出密钥，不触碰原工作区 dirty 文件，不批量迁移用户数据。

## 验收

- 解析正反样本分别验证章节内容完整、顺序、数字、目录与正文区分；不能通过丢弃未识别内容获得表面通过。
- 人物正反样本分别统计正确项、误报和遗漏；包含纯景物、普通动作短语、复姓、不同名字及旧否定回归，不能只检查人数变少。
- 离线全量、Python/JS 静态检查、diff 检查通过，无 skip、外部模型或付费请求。
- 真实本地应用与真实浏览器完成导入→编辑→保存/切章→拆解→人物/剧情→证据定位，以及旧保存/恢复/来源隔离回归；合成素材清楚标注，不冒充真实小说质量。
- 独立审计缺陷回到原实现 Agent 修复并复验。无未闭合严重问题后提交、推送并保持 Draft PR，待用户内容/视觉验收。
- 用户批准追加当前反馈作品的一次 MiMo 小样试跑，包含重试累计上限 2 元。只读原数据、私有隔离输出；逐字来源验证、人物身份/重要性、剧情语义和依据支持分别复核，不把 JSON 通过当成质量通过。

## 交付与恢复

主 Agent 维护 PROGRESS/BLOCKED、Notion 与 PR。执行者交回改动、命令结果、已知限制与提交，不改管理文档或替作者验收。只在本任务管理工作区集成，不改变原用户运行目录。原版本、数据及阶段 34 草稿均可继续使用。
