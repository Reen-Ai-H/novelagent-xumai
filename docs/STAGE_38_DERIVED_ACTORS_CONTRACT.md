# 阶段38 · 事件人物索引的单一来源

状态：2026-10-23已集成，主回归通过，独立复核及真实效果仍待完成。真实状态见PROGRESS，不代表报告内容通过。

本合同继承[来源目录合同](STAGE_38_SOURCE_REPORT_CONTRACT.md)与[稀疏人物合同](STAGE_38_SPARSE_ANALYSIS_CONTRACT.md)。只改变新私有wire的索引生成职责；用户仍从同一作品正常拆书并查看人物/事件图，不增加页面、说明小字或手工整理步骤。

## 数据职责

`source-report-v4`的事件不接收`actor_ids`。草稿、修订、规范化记录、核对材料和对应hash均使用无该字段的私有形状；不是把原始响应改写成另一份响应。最终投影时，由同事件action、consequence和sub_events的非空主客体，选出已建卡人物，按characters原数组顺序唯一列出。它表示事件主张涉及的人物，不单独证明实际到场或行动。

投影前必须验证所有非空端点存在；不能以取交集消除未知ID。派生结果超过原公共20人上限即拒绝，不截断。其余Claim、人物、背景、来源和关系原样保留；不自动删背景、补事实、改主体或合并别名。多人分工和重要参与须由真实且正确的主张表达，缺失不能由索引补齐。

新私有relations同样不含重复kind；最终从模型选择的basis按旧唯一映射派生：cause→causes、purpose→enables、before→follows、reveal→reveals、echo→foreshadow_payoff。未知basis或显式提供kind拒绝；模型仍判断basis和来源，程序不选因果类型、不反转方向、不变更动作。raw/规范稿/hash/修订不接收派生kind；旧wire一致性和所有最终语义边界保持。

公开格式仍为schema2/model.2，使用原最终完整校验与导入。v1/v2/v3旧任务、旧schema、缓存及失败记录保持原处理，不猜版本、不把旧失败稿转成v4采用。新任务持久冻结v4，恢复沿用已存wire。

## 核对与安全

模型核对仍逐章阅读全部原文，判断主配覆盖、别名、实际主体、计划与已发生、说话者与叙述者、真实时序、对外身份与实际身份、重要经历遗漏。索引可计算不等于内容正确。

所有原始text/parsed、规范稿、对象原值hash及修订前后值必须一致；恢复时不能接受外加或篡改的派生字段。动机/变化可空及已有有源Claim不得在格式修复中清空的保护继承v3。来源目录、同源CAS、身份/动作/关系/时间最终校验与采用幂等不变。

保持12条/8KiB诊断、8目标/12KiB修订，正常两阶段/修订三阶段，每阶段一次格式修复，最多六HTTP。草稿24576、review8192、verify4096上限及每HTTP双预算保持。原5元scope不重置、不增额，余额与在途只读实际账本。不得以当前失败稿的诊断数减少为真实通过证据。

## 最小验收

1. 新wire原始和规范事件无actor_ids、relations无kind；显式给这些字段严格拒绝，basis未知仍拒绝。五种basis精确派生旧kind，不改变关系方向/来源/阶段校验。旧wire逐值、默认、接受与拒绝行为不变。
2. 主客体去重且按人物数组稳定投影；null、背景个体不进入公开索引；已知/计划涉及的人不被描述成已到场。未知端点与超过20人拒绝，无截断或额外事实生成。
3. 假模型完整草稿→accept→采用及revise→verify→采用，持久重读、导出/导入、旧公开schema2网页兼容。改变主客体的有源修订必须重新派生索引，旧索引不能残留。
4. 暂停/恢复、来源改变、跨账户、原始text与parsed类型敏感、草稿/修订/原值hash、一次修订及未知请求不重发保持。缺name的既有有源Claim保护不能退化。
5. 实际fake HTTP的生成/格式修复/核对/终审均选择正确schema和提示；预估与真实逐HTTP双预算一致，不凭旧估值放行。
6. 主完整门禁至少保留951项，无跳过或弱化旧断言；不同Sol独立窄审后，才可考虑原预算内真实试验。最终必须是作者正常网站的完整六章报告、独立原文语义复核及三视口/证据回链，不由合成测试代替。
