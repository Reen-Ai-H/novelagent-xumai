# 叙脉实现阶段摘要（2026-08）

这是公开开发版的阶段摘要。原始任务现场、审计证据、账户、正文和本机路径不属于公开历史；它们留在本地受保护目录，不纳入 Git。当前实现和限制以根目录 README、PROGRESS、BLOCKED 及 `docs/` 权威文档为准。

## 阶段 1–4：产品入口与双路径基础

- 建立 A 版霜纸、墨蓝、钴蓝、朱批、书脊导航和故事脉络线。
- 完成首页、邮箱本地开发登录、持久会话、书架搜索和独立/AI 新建作品。
- 服务端保存账户、作品模式、章节统计、进度、最近编辑和开发积分；手机号/微信仅显示未开放。
- AI 作品有清晰模式标识；无模型配置时走确定性演示且不消耗创作积分。

## 阶段 5–8：独立创作、档案与安全边界

- 独立作品支持空白建书以及 TXT、MD、DOCX 导入预览确认，导入失败不会创建正式稿本。
- 三栏编辑器支持服务端自动保存、revision 冲突、完成本章后台分析、通知、章节快照和完整故事档案。
- 旧章修改统一进入待确认修改，支持轻改忽略、全文重建、30 天恢复和单一当前稿本。
- 四个档案区块使用纵向滚动锚点与唯一当前项；历史快照只读，角色默认使用非具象角色牌。
- 新旧 API 都执行会话、账户 owner 和作品归属门禁；故事角色私有记忆只在服务端单人物推演中使用。

## 阶段 10–12：档案视觉与交互收口

- 收敛故事档案底部空白，保留人物、剧情线、伏笔、疑问点四锚点和 reduced-motion 行为。
- 锚点点击意图与真实滚动意图分开处理；程序化滚动被夹到文档底部时仍保留作者明确点击的唯一当前项。
- 时间线演示状态使用简洁“演示分析”文案，不把内部配置术语当作作者提示。

## 阶段 15–18：真实模型、安全与纯文本正文

- 通过配置加载器接入 OpenAI-compatible/百炼别名和 DeepSeek 兼容运行时；无配置时明确不可用/演示，有配置时失败不静默降级。
- 主编蓝图、故事角色推演、三选一和审校/档案阶段使用严格结构化输出；每个故事人物独立组装上下文。
- 正文阶段从 JSON 协议拆出独立纯文本协议，允许自然中文中的对白、引号和大括号，并在长度、截断、私有信息命中前拒绝落库。
- 模型调用只持久化脱敏的 call_id、provider、model、usage、latency、attempts、status 和错误类别，不保存密钥、提示词或原始 completion。

## 阶段 20–22：兼容、连续章节与可观测性

- 旧项目的 naive/aware 时间在读取和排序边界统一解释为 UTC，异常时间使用稳定降级，不回写旧 JSON。
- 导演运行支持连续章节、关键节点三选一、唯一正式路线、服务端恢复和完成通知。
- 系统生成正文不创建作者待确认修改；作者后续手改仍沿用原有 pending_changes 合同。
- 每次外部尝试保留安全 usage/延迟/重试元数据，即使业务事务失败也不丢调用账本。

## 阶段 24–27：跨 store 事务与作者优先

- 引入 durable journal、staging payload、commit marker 和确定性 reconcile，未提交的新状态不对外可见。
- 多个 store 的读入口最终只能看到完整旧状态或 exactly-once 的完整新状态；重复恢复不会重复章、选择、快照、通知或积分。
- 关键选择的普通作者来源记录为 `author`，“把决定交给角色”及 worker 委托恢复记录为 `character`。
- commit marker 后出现作者新 revision 时，作者正文永远优先；可证明无冲突时幂等完成，否则收敛为 `author_revision_conflict` 可重试终态，不展示 AI 半成品。
- 阶段 27 独立审计 P0/P1/P2/P3 均为 0；真实 DeepSeek 连续三章链路已验证。
